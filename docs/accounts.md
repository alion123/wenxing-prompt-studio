# 账号与云端工作区

账号为可选功能。不配置 Supabase 时仍可使用访客工作区。配置后支持邮箱注册、验证、登录、退出当前设备和邮件重置密码。

## 部署配置

1. 在自己的 Supabase 项目 SQL Editor 执行 `supabase/migrations/20261101_accounts.sql`，建立工作区表、账号隔离策略和版本检查函数。
2. 在 Cloudflare Pages **生产环境**添加文本变量 `SUPABASE_URL` 和 `SUPABASE_PUBLISHABLE_KEY`。后者只能使用 publishable key 或旧版 anon key；绝对不要填写 secret / service_role key。原有 `DEEPSEEK_API_KEY` 仍作为服务端机密保留。
3. 在 Supabase → Authentication → URL Configuration，将 Site URL 与 Redirect URLs 都设置为实际使用的正式站点地址，例如 `https://example.pages.dev`。换域名后需同步修改。开发和预览站点如需接收邮件跳转，也需分别加入允许列表。
4. 在 Authentication → Emails → SMTP Settings 配置自定义邮件服务，并保留邮箱确认。Supabase 默认邮件服务不适合公众注册；未完成 SMTP 前，不应宣称任意用户都能收到验证或找回密码邮件。
5. 重新构建并部署。检查 `/api/auth-config` 仅返回项目 URL 和公开 key；未配置时两项均为 null。
6. 用真实邮箱完成注册验证、登录、重置密码并打开邮件链接，确认跳回正式域名。密码至少 8 位，访客功能不要求注册。

## 数据规则

- 访客与每个登录账号使用不同的浏览器存储键。切换账号后不会自动带入上一账号或访客数据。
- 迁移访客项目：先在访客工作区下载 JSON 备份，登录后在“问形服务”中导入。导入包含参考图片、回答及历史版本，操作前自行核对。
- 云端保存和读取均为手动操作。登录后点击“我的账号”，先检查云端版本，再保存当前工作区。
- 读取云端会先展示确认，确认后合并到本地；相同项目跳过，存在差异的同编号项目另存一份，保留本地内容。
- 其他设备更新了云端后，旧版本保存会被阻止。先读取并合并云端，再保存。不要仅靠刷新版本号强行覆盖。
- 云端保存包含项目、常用提示词、问答、版本和压缩参考图，最大 10 MB。只保存在当前浏览器的改动不会自动上传。
- 数据库使用 RLS，通过当前认证用户的 UUID 限制读写；服务端函数使用 SECURITY INVOKER。浏览器不需要管理员数据库密钥。
- 退出账号不会删除该账号在这台设备的本地缓存。共享设备上使用后应清理浏览器站点数据，清理前先保存或备份。

## 验证

`npm test`、`npm run typecheck`、`npm run build:pages` 验证本地实现。`supabase/isolation-test.sql` 在事务中创建两个临时账号并验证账号读写隔离与过期版本冲突，最后回滚所有测试数据。仅由项目管理员在测试环境或明确授权的项目执行。

界面网络桩测试与数据库权限测试不能代替真实验证邮件和重置邮件的端到端测试；后者必须在邮件服务配置完成后单独验证。
