代码提示词怎么写：从需求到验收

把代码任务的功能、输入输出、技术限制和验收条件说清楚，减少生成后返工。

先明确要解决的问题

先说谁会使用、在什么设备上用、最重要的操作是什么。例如“给学生做一个离线记账网页，可以新增支出和按月汇总”。不要只写“做得高级一点”。

再补齐边界

说明是否需要登录、数据保存在哪里、是否支持手机，以及已有代码和必须沿用的技术。没有明确偏好时，请问形列出假设，确认后再生成。

最后写出能检查的结果

例如：新增一条支出后，本月合计立即更新；刷新后记录仍在；非法金额不能保存。让 AI 输出运行方法和已知限制。

可以直接改写的示例

请开发一个面向个人使用的离线记账网页。支持新增、编辑和删除支出，字段为金额、分类、日期和备注。按月份筛选，并显示分类汇总。数据保存在当前浏览器，首次使用不要求注册。使用清晰的中文界面，适配手机。金额必须大于0，提交失败时保留输入。交付可运行代码、启动步骤，以及新增支出、刷新保留记录、编辑金额和删除记录的验证方法。

用问形继续完善

选择相应方向，写下一句话想法，再回答几个问题。不确定的部分可以交给问形提出建议；预览初稿后继续优化，也可以返回前面的步骤修改。
